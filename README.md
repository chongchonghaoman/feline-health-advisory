# 一名合格且专业的铲屎官.skill

> 给合格且专业的铲屎官用的猫咪急症红旗分诊 skill：问 AI 之前，先别喂药、别拖到明天、别把急症当“小毛病”。
> 它会先识别急症红旗，再补齐必要病史，最后给出安全、可执行的下一步。

英文代号：**Feline Health Advisory**
内部调用名：`$feline-health-advisory`

## 先说边界

这个 skill 只做猫咪健康与行为问题的风险分诊和照护提醒，不替代兽医诊断、检查或治疗。
如果出现无法排尿、呼吸异常、疑似中毒、抽搐、严重外伤、幼猫虚弱、难产等情况，应该立即联系兽医或急诊动物医院，而不是等待 AI 慢慢排查。

有些猫咪问题，最怕的不是“不知道”，而是被一句“再观察看看”耽误：

- 公猫反复蹲猫砂盆，每次只有几滴尿，可能不是“上火”。
- 猫舔了百合叶子，就算现在看着正常，也不能只靠观察。
- 猫吐了几次，不等于可以先喂蒙脱石散。
- 老猫突然喝水多、变瘦、半夜叫，不一定只是年纪大。
- 小奶猫体冷、不吃奶，强行灌奶可能更危险。

这个 skill 的目标不是让 AI 像兽医一样远程诊断，而是让 AI 先做一件更重要的事：**别漏掉该立刻就医的危险信号**。

## 铲屎官先看这里

### 这 8 种别等

- 公猫反复蹲猫砂盆、尿很少或没尿。
- 呼吸费力、肚子明显起伏、伸脖子呼吸、不能趴下睡。
- 百合、人药、狗用驱虫药、老鼠药、清洁剂、精油等疑似接触。
- 抽搐、突然瘫软、昏厥、站不起来。
- 车祸、高处坠落、被咬、开放伤、大出血。
- 反复呕吐，喝水也吐，或疑似吞线绳/针/异物。
- 幼猫体冷、不吃奶、虚弱、体重不增。
- 老年猫突然失明、后腿拖行、脚冰凉疼痛、严重虚弱。

### 国内铲屎官急症三步

1. 搜或打电话问：`24小时 宠物急诊`、`动物医院 急诊`、`夜间急诊`。
2. 电话里先说关键词：无法排尿、呼吸困难、疑似中毒、抽搐、被咬、幼猫体冷、难产等。
3. 去医院前带上：症状视频、时间线、排尿排便记录、药品/植物/清洁剂/驱虫药包装或照片。

如果找不到毒物热线，直接联系最近的急诊动物医院或有急诊能力的宠物医院。安装失败、网络拉不下来、不会用 Git，都不要耽误急症处理。

## 为什么值得留着

- **先分诊，再科普**：不会一上来长篇解释，却忘了判断是不是急症。
- **先排雷，再建议**：会拦住人药、偏方、剂量、拖延就医这类高风险回答。
- **先问关键病史**：年龄、绝育、排尿、吃喝、精神状态、毒物接触，不靠猜。
- **先给下一步**：什么时候急诊、什么时候当日就诊、什么时候可以短期观察，说清楚。
- **能审猫食品商品**：先锁 SKU、找配料/背标/保证分析，再判断能不能给猫吃；不会因为旗舰店、好价或爱吃就直接说安全。
- **适合中文铲屎官语境**：能识别“上火”“报复我”“先喂点药”“明天再去”等真实表达里的风险。

## 它解决什么问题

很多宠物问答翻车，不是因为知识少，而是顺序错了。

铲屎官问“是不是上火”，AI 不能先讲泌尿科普；
铲屎官问“能不能喂点药”，AI 不能顺着给家庭用药方案；
铲屎官说“现在看着还好”，AI 不能把这句话当成安全保证。

这个 Skill 强制 AI 按下面的顺序回答：

1. **先看急症红旗**
   尿闭、呼吸困难、中毒、抽搐、外伤、难产、幼猫虚弱、老年急变等，先建议急诊或当日就医。

2. **再问最少必要病史**
   年龄、性别/绝育、症状开始时间、吃喝、排尿排便、精神状态、是否接触毒物或人药。

3. **再参考公开可查资料做风险提示**
   优先参考兽医协会、大学兽医学院、毒物咨询和兽医手册资料，不用偏方帖、带货帖或群友经验替代。

4. **最后给清晰下一步**
   什么时候观察，什么时候预约，什么时候急诊，去医院前该带什么资料。

商品审查会按另一条硬流程走：

1. **先锁商品**
   用商品名、短链、平台、店铺、规格、口味、价格和图片交叉确认，不把相似 SKU 的配方套过来。

2. **再找背标**
   优先找包装背标、官方详情图、旗舰店详情图、品牌官网、清晰买家晒图；必要时用本机 OCR 辅助读图。
   用户要求必须拿到准确配料时，启用硬获取模式：平台聚合检索、图片 OCR、全网精确查询、登录页面长截图、客服索取中文标签逐级升级。

3. **再分证据等级**
   A/B 级才算核到配料；C 级只能临时参考；D 级就是没找到准确配料表。

4. **最后判断适不适合这只猫**
   幼猫、成猫、慢病猫、主食、零食、试吃、长期囤货分开说，价格永远放最后。

## 适合谁

- 想给 AI 加上猫咪健康分诊能力的铲屎官
- 想做宠物健康问答、猫咪护理助手、铲屎官教育 bot 的开发者
- 经常处理猫咪护理、猫砂盆、呕吐、误食、老年猫、幼猫问题的内容创作者
- 希望减少“偏方、人药、延误急诊”风险的 AI 工作流维护者
- 想把猫咪行为问题和潜在医学原因分开处理的铲屎官

## 不做什么

这个项目刻意不做远程诊断，也不做远程处方。

- 不给具体药物剂量
- 不建议自行使用人药
- 不替代兽医诊断
- 不把“看着还好”当成中毒或急症的安全保证
- 不因为预算、距离、时间不便而降低急症等级

这不是不专业，而是边界感。猫的用药安全窗很窄，剂量需要诊断、体重、年龄、脱水状态、肝肾功能和监测条件一起判断。

## 快速安装

你需要：已安装 Codex、能打开终端/PowerShell、能访问 GitHub。不会安装也没关系，先用上面的复制模板。

把这个仓库放到你的 Codex 或 WorkBuddy skills 目录中。

Codex 示例：

```bash
git clone https://github.com/chongchonghaoman/feline-health-advisory.git ~/.codex/skills/feline-health-advisory
```

Windows / Codex 示例：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex\skills"
git clone https://github.com/chongchonghaoman/feline-health-advisory.git "$env:USERPROFILE\.codex\skills\feline-health-advisory"
```

WorkBuddy 示例：

```bash
git clone https://github.com/chongchonghaoman/feline-health-advisory.git ~/.workbuddy/skills/feline-health-advisory
```

Windows / WorkBuddy 示例：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.workbuddy\skills"
git clone https://github.com/chongchonghaoman/feline-health-advisory.git "$env:USERPROFILE\.workbuddy\skills\feline-health-advisory"
```

然后关闭并重启对应应用，在对话里显式调用：

```text
Use $feline-health-advisory：我家猫今天一直蹲猫砂盆，但尿很少。
```

如果提示 `git` 不是命令：先安装 Git，或直接使用“不会安装也能直接用”模板。
如果提示目录已存在：可能已经安装过，重启 Codex 后再试。
如果 GitHub 拉不下来：先用复制模板，不要因为安装问题耽误猫咪急症判断。

## 示例问题

```text
我家公猫一晚上进猫砂盆十几次，每次就几滴，还一直舔下面，是不是上火？
```

它应该怎么答：识别尿道阻塞风险，建议立即急诊，不建议等到明天或喂偏方。

示例回答片段：

```text
这属于急诊风险，尤其是公猫反复蹲盆但尿很少，要优先考虑尿道阻塞风险。建议现在联系急诊动物医院，不要等到明天，也不要喂偏方或自行按压腹部。
```

```text
猫舔了一下百合叶子，现在吃喝正常，需要观察吗？
```

它应该怎么答：说明百合暴露即使暂时无症状也可能紧急，建议联系急诊兽医或毒物咨询。

示例回答片段：

```text
百合对猫属于高风险暴露，即使现在吃喝正常，也不建议只观察。请尽快联系急诊兽医或有急诊能力的动物医院，带上植物照片或实物信息。不要自行催吐、灌水、喂奶或喂油。
```

```text
猫突然尿床，是不是报复我出差？
```

它应该怎么答：先排除泌尿疼痛、尿频尿血等医学原因，再讨论猫砂盆、压力和环境。

示例回答片段：

```text
不要先按“报复”处理。突然尿床需要先排除泌尿疼痛、尿频、尿血、尿量异常等医学原因。先确认最近有没有正常尿团、是否频繁进盆、是否痛叫，再考虑猫砂盆和压力因素。
```


核心文件：

- `SKILL.md`：执行协议，定义触发、分诊顺序、禁止项和语言策略。
- `triage_red_flags.md`：急症红旗，包括尿闭、中毒、呼吸、产科、幼猫、老年猫急变。
- `intake_questions.md`：最小病史采集模板。
- `scenario_routes.md`：疾病、行为、猫砂盆、疫苗、营养、幼猫、老年猫、中毒等主题路由。
- `product_assessment.md`：猫食品商品审查流程，覆盖 SKU 锁定、背标证据等级、硬获取模式、中文电商探针、OCR 辅助和幼猫适配。
- `cn_ecommerce_label_probe.py`：调用已安装的 `maishou` skill 搜索淘宝/天猫、京东、拼多多等候选商品和详情图，可用 `--require-label` 强制在未找到强标签字段时失败。
- `product_label_audit.py`：下载候选图片，做预处理，并用 Tesseract OCR 抽取配料/保证分析等标签线索。
- `sources.yaml`：结构化来源登记。
- `eval_cases.yaml`：对抗性回归测试用例。

## 设计原则

### Emergency first

急症回答先给行动，再解释背景。不要让引用、科普或长篇分析挡在“现在去急诊”前面。

### Triage, not diagnosis

回答风险等级和下一步，不把 AI 变成远程兽医。

### 铲屎官友好的语言

用合格且专业的铲屎官听得懂、做得到的语言说清楚：该观察什么、带什么去医院、哪些事不要做。

### Source-aware

涉及“最新”“当前”“本地”“疫苗程序”“召回”“地区风险”时，需要核验官方来源。无法核验时，必须说明不确定。
