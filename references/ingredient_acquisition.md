# 猫食品配料表获取 SOP

当用户要求“找到配料表、准确配料信息、原料组成、成分分析保证值、背标、包装背面”时，读本文件。目标是尽最大努力拿到目标 SKU 的配料表原图、官方字段或可复核文字，再谈购买建议。

“未核到/未验证”只能是中间状态或被阻断说明，不能代替查找动作本身。

## 成功和退出条件

- **成功**：拿到目标 SKU 对应的原料组成/配料、添加剂组成、产品成分分析保证值中至少一个核心字段，并能说明来源、链接/图片、规格、口味和证据等级。
- **部分成功**：已锁定 SKU 或找到条码/平台商品号/官方商品页，但尚未拿到配料字段；继续沿图片、缓存、OCR、客服或用户补图路径获取。
- **被阻断**：只有在公开检索、平台探针、官方页/旗舰店页、图片/OCR、缓存、条码桥接、客服索取或用户补图路径都明确尝试或确实不可用后，才写“当前拿不到准确配料表”。
- **禁止偷懒式完成**：不要只输出“未找到准确配料表/证据不足/不建议囤”。必须列出已查路径、最可能继续出配料的候选链接或图片位置、下一条 query、要问客服的字段，或要用户补的最小截图。

## 第一性原则

准确配料信息必须同时满足：

1. **SKU 准确**：品牌、官方品名、系列、规格、口味、适用阶段、包装版本、目标市场、平台商品 ID/规格选项和 GTIN/商品条码能对上。40g*3、40g*6、40g*9、餐盒/餐包/猫条/幼猫款不能互相套用。
2. **来源可追溯**：配料来自包装背标、官方详情页、旗舰店详情图、品牌官网、平台商品图或清晰买家晒图；必须能给出链接、图片来源或用户提供的图片。
3. **字段完整**：至少尝试找原料组成/配料、添加剂组成、产品成分分析保证值、适用阶段、净含量、产品标准号、生产/委托信息。
4. **OCR 可复核**：OCR 结果只能做辅助；关键字段要结合肉眼检查，不能把 OCR 错字当事实。
5. **身份与配料分离**：平台商品号、GTIN、GLN、厂商前缀、GS1/GDS/GDSN/Verified by GS1 命中，默认只能证明身份线索；除非同一记录明确展示配料字段或标签图，否则不能写“已查到配料”。
6. **条码层级不互通**：单包码、内包装码、外箱码、销售组合码、混合装码互不等价。混合装必须逐个组件核标签，或拿到官方完整口味矩阵。

## 证据等级

- `A 级`：包装背标清晰图，或品牌/旗舰店详情图中完整标签；可作为“已找到准确配料信息”。
- `B 级`：官方详情页文字或官方页面中的配料/保证分析，但没有完整背标；可作为“官方配料信息”，仍标注缺少背标。
- `C 级`：平台/导购/聚合页商品图、买家晒图、测评图能看清配料；可用于临时判断，但必须标注非官方或来源限制。
- `D 级`：只有卖点图、价格线报、达人文案、口碑描述、相似 SKU、其他规格/口味配方；不能当准确配料信息。

只有 A/B 级可以说“配料信息已核到”。C 级说“看起来能读到配料，但需官方/背标复核”。D 级只能说“未找到准确配料表”。

## 标准查找顺序

按顺序执行，除非已经拿到 A 级证据：

1. **商品名文本反搜**：完整商品名加引号；组合 `配料表`、`原料组成`、`成分分析保证值`、`背标`、`包装背面`、`详情图`、`产品标准`、`买家晒图`。
2. **SKU 关键词拆解**：从标题、短链、平台、店铺、主图文字、口味、净含量、item id、京东 SKU、英文标签词、包装正面内部码拆关键词。淘宝/京东/拼多多短链先抽真实目标地址、`id=`、`itemNumId`、`skuId` 或平台商品号。
3. **官方与邻近 SKU 校验**：查品牌官网、旗舰店详情页、官方小程序/公众号、京东/天猫/拼多多官方店公开图。相似系列只能标为线索，不能直接套用。
4. **海外同款/官方店镜像**：国内页面不给背标时，必须用品牌英文名、包装英文、系列英文、口味英文和净含量查海外官方站、Shopee、Lazada、Amazon、独立站、TikTok Shop 等同款页。规格不同必须写成“同款/同系列配方证据，国内精确销售规格仍需核”。
5. **条码/GTIN 身份核验**：搜索 `商品名 + 商品条码/GTIN/EAN/条形码`、`包装内部码 + 条码`。GS1/GDS/GDSN/中国商品信息服务平台只用于核品牌、规格、目标市场和条码单位；没有配料字段或标签图时不能当配料证据。
6. **中文电商探针**：运行 `scripts/cn_ecommerce_label_probe.py` 锁定候选商品、店铺、价格、主图、详情图和购买链接。这个步骤只用于找 SKU 和候选证据。
7. **平台与社媒图片源**：用图片搜索、平台评价晒图、小红书/测评文章寻找背标。社媒来源只当图片证据。
8. **缓存与历史图源**：查搜索引擎索引摘要、移动端短链跳转页、平台静态 HTML、图片 CDN 原图 URL、历史详情图缓存、导购站缓存。
9. **OCR 与人工复核**：下载候选图运行 `scripts/product_label_audit.py` 或直接用 tesseract。脚本没有命中标签不代表图片没有配料；如果 `ocr_chars` 明显大于 0，必须打开 `ocr_text_path` 搜英文/数字字段，并用原图肉眼复核。
10. **客服/实物层**：平台详情没有背标时，要求旗舰店客服提供中文标签照片；用户已购买时，要求拍包装背面。需要字段：配料表/原料组成、添加剂组成、产品成分分析保证值、适用生命阶段、产品标准号、生产或进口信息。

## 英文标签词

海外页或英文详情图必须搜这些词：

- `Raw Material Composition`
- `Additive Composition`
- `Dry Matter Basis`
- `Ingredients`
- `Analytical constituents`
- `Guaranteed analysis`
- `Crude protein`
- `Crude fat`
- `Crude fiber` / `Crude fibre`
- `Crude ash`
- `Moisture`
- `Taurine`
- `Total phosphorus` / `Phosphorus`
- `Calcium`

## 鲜朗式实战 SOP

遇到“国内商品名找不到背标，但同款可能有海外详情图”的产品，固定执行：

1. 国内电商先锁候选：用 `maishou` 搜淘宝/天猫、京东、拼多多，记录最像目标的标题、店铺、价格、销售组合、主图、详情图和链接。
2. 识别真实销售规格：把用户说的规格和页面读到的规格分开，例如 `50g*3`、`50g*6`、`50g*9` 可能只是销售组合不同，不能默认等同；先找单包净含量、口味和系列是否一致。
3. 国内详情图跑 OCR：主图、详情图逐张跑 `product_label_audit.py`，但脚本没命中时也要看 `ocr_text_path` 和原图。
4. 查海外官方/同款页：用品牌英文、包装英文、系列英文和口味英文搜索，例如 `Rosy Fresh/Freshly Fresh + staple cat food + chicken beef salmon + composition`；优先打开官方店或可和包装一致的同款页。
5. 抓海外详情图并 OCR：逐张下载/OCR，重点搜英文标签词。脚本 `has_label_evidence=false` 时也要人工看图。
6. 肉眼复核并摘录：打开本地图片，用肉眼确认原料百分比、添加剂、保证分析值，按口味分别摘录，不用 OCR 错字直接下结论。
7. 输出证据边界：如果拿到的是海外官方页/同系列销售组合，写“已拿到同款/同系列配料证据；国内精确 SKU/销售组合仍需用链接、背标或客服复核”。这比“未验证”有用，但不能说国内精确规格背标已核。

## 脚本辅助

```bash
python scripts/cn_ecommerce_label_probe.py "完整商品名或用户给出的商品标题" --source 0 --top 10 --detail-top 3
python scripts/cn_ecommerce_label_probe.py "完整商品名或用户给出的商品标题" --source 0 --top 5 --detail-top 2 --ocr
python scripts/cn_ecommerce_label_probe.py "完整商品名或用户给出的商品标题" --source 0 --top 5 --detail-top 3 --ocr --require-label --report evidence.json
python scripts/product_label_audit.py --query "完整商品名" --url "商品或聚合页 URL"
python scripts/product_label_audit.py --query "完整商品名" --image "本地图片或图片 URL"
```

`cn_ecommerce_label_probe.py` 用于 SKU 定位和取图。`product_label_audit.py` 用于下载候选图片、预处理、OCR、抽取中英文标签线索。脚本输出不是最终结论，只是证据篮子；最终回答必须人工判断 SKU 是否一致、图片是否完整、OCR 是否误读。

## 输出要求

每个商品按这些字段输出：

- **SKU 锁定**：核到的品牌、规格、口味、链接/图片来源；若不确定，直接写不确定。
- **身份确认**：平台商品 ID/SKU、GTIN/条码、条码单位、目标市场和包装版本是否匹配；只查到身份码时不能写已核配料。
- **配料证据等级**：A/B/C/D。
- **配料确认 / 保证分析确认**：分开写是否已核到原料组成/添加剂组成，以及是否已核到产品成分分析保证值。
- **已读到的配料/标签字段**：只写看清或 OCR 后人工确认的内容；看不清就写“看不清”。
- **还缺什么**：缺背标、保证分析、添加剂组成、标准号、批号或生产信息。
- **已执行的获取路径**：列出已查的官方页、平台、搜索式、候选图、OCR、条码/数据库或客服路径。国内详情页没有背标时，必须单列“海外/英文分支”，说明已用哪些品牌英文名、包装英文、系列英文、口味英文、`composition`、`ingredients`、`analytical constituents` 等查询词检索过，以及是否命中同款/同系列官方页或平台页；不能把这一步省略成一句“未找到”。
- **下一步获取动作**：具体到继续打开哪条链接、搜哪条 query、看哪张图、问客服哪几个字段，或让用户补哪张规格/背标截图。
- **给 mobi 的临时判断**：在证据等级基础上说可试/先别囤/不建议当主食；不要让价格和爱吃压过标签证据。
