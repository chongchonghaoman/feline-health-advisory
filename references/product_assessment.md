# 猫食品商品审查流程

当用户给出猫粮、主食餐盒、主食罐、主食猫条、餐包、冻干、零食、营养补充品或多个商品让你判断“能不能买、适不适合我的猫、健不健康、合不合规、安不安全”时，按本流程处理。

本流程不替代兽医营养处方。慢病、长期厌食、减重、肾病、糖尿病、胰腺炎、食物过敏、反复呕吐腹泻或幼猫发育异常，先回到分诊和兽医评估。

## 先问或提取的信息

优先从用户消息中提取；缺失时只追问会改变结论的 3-6 项。

- 猫：年龄、体重、性别/绝育、品种或体型、是否幼猫/老年、疫苗驱虫、慢病、近期呕吐腹泻、软便、拒食、体重变化。
- 商品：品牌、完整商品名、规格、口味、价格、购买渠道、是否旗舰店、是否国产/进口、是否只打算试吃还是长期主食。
- 标签证据：正面品名、背面配料表、营养成分/保证分析、适用生命阶段、产品标准号、生产企业/委托方、生产许可证或进口信息、生产日期、批号、保质期。
- 公开信息：品牌官网/旗舰店详情页、平台评价、近期投诉、官方召回或监管通报。

如果缺少配料表和保证分析，不要给“品质很好/完全合规/放心囤”的结论；最多给基于已核信息的临时建议。

## 配料查找模式

当用户明确要求“找到配料表、准确配料信息、原料组成、成分分析保证值、背标”时，切换到配料查找模式。目标不是尽快给购买建议，而是先把配料证据找扎实。

### 第一性原则

准确配料信息必须同时满足：

1. **SKU 准确**：品牌、商品名、规格、口味、适用阶段、包装版本能对上。40g*6、40g*18、80g*4、餐盒/餐包/猫条/幼猫款不能互相套用。
2. **来源可追溯**：配料来自包装背标、官方详情页、旗舰店详情图、品牌官网、平台商品图或清晰买家晒图；必须能给出链接、图片来源或用户提供的图片。
3. **字段完整**：至少尝试找原料组成/配料、添加剂组成、产品成分分析保证值、适用阶段、净含量、产品标准号、生产/委托信息。
4. **OCR 可复核**：如果配料来自图片，OCR 结果只能做辅助；关键字段要结合肉眼检查，不能把 OCR 错字当事实。

### 证据等级

- `A 级`：包装背标清晰图，或品牌/旗舰店详情图中完整标签；可作为“已找到准确配料信息”。
- `B 级`：官方详情页文字或官方页面中的配料/保证分析，但没有完整背标；可作为“官方配料信息”，仍标注缺少背标。
- `C 级`：平台/导购/聚合页商品图、买家晒图、测评图能看清配料；可用于临时判断，但必须标注非官方或来源限制。
- `D 级`：只有卖点图、价格线报、达人文案、口碑描述、相似 SKU、其他规格/口味配方；不能当准确配料信息。

只有 A/B 级可以说“配料信息已核到”。C 级说“看起来能读到配料，但需官方/背标复核”。D 级只能说“未找到准确配料表”。

### 查找顺序

按顺序执行，除非已经拿到 A 级证据：

1. **精确搜索**：用完整商品名加引号，组合 `配料表`、`原料组成`、`成分分析保证值`、`背标`、`包装背面`、`详情图`、`产品标准`、`买家晒图`。
2. **SKU 反查**：从线报/导购页提取商品主图、短链、item id、京东 SKU、规格和口味；确认到底是哪一款。
3. **中文电商探针**：如果本机已安装 `maishou` skill，运行 `scripts/cn_ecommerce_label_probe.py`，在淘宝/天猫、京东、拼多多等平台锁定候选商品、店铺、价格、主图、详情图和购买链接。这个步骤只用于找 SKU 和图片，不等于已经核到配料。
4. **官方源**：查品牌官网、旗舰店详情页、官方小程序/公众号、京东/天猫/拼多多官方店公开图。
5. **图片源**：用图片搜索、平台评价晒图、小红书/测评文章寻找背标。社媒来源只当图片证据，不当权威背书。
6. **OCR 与人工复核**：下载候选图，运行 `scripts/product_label_audit.py` 或直接用 tesseract；只摘录能看清的字段。
7. **仍找不到**：明确列出已查路径和缺口，再要求用户补“包装背面清晰图/详情页配料图/商品链接”。不要装作已经找到。

### 脚本辅助

优先用脚本处理候选图片和静态页面：

```bash
python scripts/cn_ecommerce_label_probe.py "完整商品名或用户给出的商品标题" --source 0 --top 10 --detail-top 3
python scripts/cn_ecommerce_label_probe.py "完整商品名或用户给出的商品标题" --source 0 --top 5 --detail-top 2 --ocr
python scripts/product_label_audit.py --query "完整商品名" --url "商品或聚合页 URL"
python scripts/product_label_audit.py --query "完整商品名" --image "本地图片或图片 URL"
```

`cn_ecommerce_label_probe.py` 会：

- 调用已安装的 `maishou` skill 搜索淘宝/天猫、京东、拼多多等中文电商商品。
- 输出候选商品的 `goodsId`、平台、店铺、价格、销量、主图、详情图和购买链接。
- 在加 `--ocr` 时，把候选详情图交给 `product_label_audit.py` 做 OCR 初筛。
- 帮助定位“该看哪张图/哪个 SKU”，但它本身不是权威配料来源。

`product_label_audit.py` 会：

- 生成应继续搜索的精确 query。
- 从静态 HTML 中抽取候选图片并下载。
- 调用本机 `tesseract` 做 `chi_sim+eng` OCR。
- 抽取命中 `原料组成/配料/添加剂/成分分析保证值/粗蛋白/适用阶段/产品标准/生产企业` 等关键词的上下文。

脚本输出不是最终结论，只是证据篮子。最终回答必须人工判断 SKU 是否一致、图片是否完整、OCR 是否误读。

### 输出要求

配料查找模式下，每个商品用这 5 项输出：

- **SKU 锁定**：我核到的品牌、规格、口味、链接/图片来源；若不确定，直接写不确定。
- **配料证据等级**：A/B/C/D。
- **已读到的配料/标签字段**：只写看清或 OCR 后人工确认的内容；看不清就写“看不清”。
- **还缺什么**：缺背标、保证分析、添加剂组成、标准号、批号或生产信息。
- **给 mobi 的临时判断**：在证据等级基础上说可试/先别囤/不建议当主食；不要让价格和爱吃压过标签证据。

## 审查顺序

1. **急症和不良反应先行**  
   如果猫已出现反复呕吐、水样腹泻、便血、精神差、拒食、脱水、抽搐、疑似异物或多猫同批食物后发病，先按 `triage_red_flags.md` 分诊。不要继续做购物分析。

2. **确认商品身份**  
   用商品名、规格、口味、官方店铺、详情页图片和价格交叉确认。多个相似 SKU 时，明确“我核到的是哪一款”；无法确认时标为“未完全匹配”，不要把别的口味或规格的配方套上去。

3. **判定食品类别与生命阶段**  
   区分全价主食、补充性湿粮/零食、主食猫条、普通猫条、营养膏/补充剂。给幼猫长期吃的主食必须满足“全价/完整均衡”且适合幼猫或全生命阶段；只标“成猫”“零食”“补充饲料/其他宠物饲料”的产品，不建议作为 mobi 这类幼猫的长期主食。

4. **合规标签检查**  
   面向中国商品时，优先检查是否有清晰品名、净含量、原料组成、添加剂组成、产品成分分析保证值、适用阶段、产品标准号、生产企业/委托生产信息、保质期、贮存条件、批号/日期、进口登记或中文标签。  
   不要因为“旗舰店”就默认合规；旗舰店只能降低渠道风险，不能替代标签审查。

5. **营养与健康适配**  
   先用 WSAVA 营养评估原则看生命阶段、体况、体重趋势、饮食史和慢病风险；再看该商品是否能承担用户想让它承担的角色。  
   - 幼猫：优先完整均衡、适合生命阶段、稳定进食、便便稳定、体重增长。新口味先 5-10g 试吃；40g 对 2-3 月龄幼猫通常更像一小餐，不算“极少量试吃”。  
   - 湿粮/餐盒/餐包：即使比干粮更容易接受，也要看是否全价、营养保证和开封保存；不要把“爱吃”当作健康证明。  
   - 猫条：除非标签明确全价且有完整保证分析，否则默认按零食或诱食辅助处理，不当长期主食。  
   - 鱼类口味：可轮换或试吃，但不建议让幼猫长期只吃鱼口味，避免口味固化和配方单一。

6. **安全与风评**  
   分开看官方召回/监管通报、批次问题、平台差评、社媒口碑和个体软便。  
   - 官方召回、监管抽检、批次污染或大面积同症状投诉，权重大于零散好评。  
   - 平台好评数量只能说明销量和满意度，不能证明配方安全。  
   - “很多猫爱吃”不等于适合作主食；“有软便差评”也不等于所有猫不能吃，要看是否集中在同批次、同口味、同症状。

7. **价格只放最后**  
   价格用于判断是否“值得买/值得囤”，不是安全性的核心证据。先给健康、合规、安全结论，再说价格处在历史低位、近期好价、普通价还是信息不足。

## 输出格式

默认简洁，不做冗长来源表。多个商品可用表格。

每个商品至少给四个字段：

- **结论**：可买 / 可少量试 / 暂不建议 / 不建议当主食 / 信息不足先别囤。
- **适合谁**：是否适合当前这只猫的年龄、体况、主食或零食用途。
- **已核依据**：商品身份、标签、官方来源、监管/标准、口碑或价格中已经核到的事实。
- **缺口和下一步**：还缺配料表、保证分析、批号、标准号、旗舰店链接、评价截图等哪一项；用户要怎么补图或怎么买得更稳。

建议用这些分层词：

- `已核`：有官方页面、包装图、监管/标准平台或可核验详情页支持。
- `未核`：公开网页没有完整配料/保证分析/批号，或 SKU 没完全匹配。
- `存疑`：价格异常低、标签缺关键项、品类和用户用途不匹配、品牌/代工信息混乱、近期集中差评。

## 禁止与边界

- 不把未看到的配料表、保证分析或标签内容当成事实。
- 不因为价格低、销量高、旗舰店、达人推荐、小红书风评就下“安全健康”的结论。
- 不给慢病处方粮、减肥热量、补充剂或益生菌剂量；需要兽医营养方案时明确转兽医。
- 不做诽谤式判断。没有可靠证据时说“信息不足/未核到”，不要说品牌一定有问题。
- 不建议囤大量新产品给幼猫。先小量试吃，观察 24-48 小时大便、呕吐、精神和食欲。

## 常见结论模板

- “这款可以少量试，不建议现在囤：我能核到商品和价格，但没核到完整配料表/保证分析。给 mobi 这种幼猫，先按 5-10g 试吃，便便稳定再增加。”
- “这款不建议当主食：它更像零食/猫条，未看到全价和生命阶段信息。可以偶尔诱食，但不能替代完整均衡主食。”
- “这款暂不建议买：价格很低但公开信息不足，SKU 没完全匹配，幼猫不拿来赌。除非你补包装背面和旗舰店链接再审。”
- “这款可作为轮换主食候选：已核到全价、适合生命阶段、标签关键项和渠道；仍需按换粮/试吃观察，不因爱吃就一次喂太多或长期单一口味。”
